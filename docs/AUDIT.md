This maps everything in `docs/DESIGN.md`, `docs/SUMMARY-SPEC.md` and the feature table in `docs/BUILD-PLAN.md` against the code that exists today, lists the technical risks, and says what each phase can reuse. Source of truth for "what's already built" when a `/clear`'d session needs to catch up.

## 1. What exists today (architecture snapshot)

- **Expo SDK 54 / RN 0.81 / TypeScript**, expo-router with typed routes. iOS + web + Android.
- **Persistence: on-device SQLite only** (`src/lib/db.ts`, `studiply.db`, WAL). No backend, no remote auth, no sync. Tables: `profiles, projects, folders, sessions, source_files, transcripts, notes, ai_usage, user_settings`.
- **Auth is local-only**: a "profile" per device, active id in AsyncStorage (`src/lib/session.ts`, `auth.service.ts`, `AuthProvider.tsx`). Explicitly *not* a security boundary.
- **AI is called from the client** with `EXPO_PUBLIC_OPENAI_API_KEY` / `EXPO_PUBLIC_ANTHROPIC_API_KEY` (`ai.service.ts`, `credit-check.service.ts`). Without keys, a full **mock pipeline** runs so non-AI features work offline.
- **Current models**: Whisper `whisper-1` (transcription), Claude `claude-sonnet-4-6` (note generation / clarify), Claude `claude-haiku-4-5-20251001` (credit check ping). A legacy id `claude-sonnet-4-20250514` appears in usage logging.
- **Recording** lives in `app/(main)/record/*` using **expo-av**, in **20-minute chunks** (3-hour cap), transcribed **after** the session (not live).
- **Notes are structured fields** (summary, key concepts, formulas, definitions, tags, unclear parts, manual annotations) — *not* a rich-text ProseMirror document. The "editor" is field edit + sentence highlighting + AI clarify, not a Google-Docs editor.
- Shared layering: screens (`app/`) → services (`src/services/`) → `db.ts`/`mappers.ts`. No screen writes SQL.

**The headline gap:** the whole app is single-device, offline, keys-in-bundle. Phase 1 (Supabase backend + Edge Functions) rebuilds that foundation; most of the designed "study" features (marks, live notes, rich editor, slider-driven summaries, assistant chat) do not exist yet in any form.

## 3. Technical risks

1. **`expo-av` is deprecated** and is the current recorder (`record/active.tsx`, `record/index.tsx`, `app.json` plugin). Phase 5 must migrate to **expo-audio**; chunking/background behaviour will need re-proving (Step 5.1 spike).
2. **`EXPO_PUBLIC_*` API keys ship in the JS bundle** (`ai.service.ts`, `credit-check.service.ts`; documented in README). Anyone can extract them → spend Lea's money. Hard blocker for App Store; removed in Phase 1 (Step 1.7 verifies zero keys in the web bundle).
3. **Whisper 25 MB per-request limit** is enforced client-side per chunk in `ai.service.transcribeAudio`. The move to 30-second live chunks (Phase 5) changes the shape of this; chunk-join gaps/overlaps are the real risk (Step 5.1 measures them).
4. **Live transcription doesn't exist** — current transcription is post-session and chunks are 20 min. The live-chunk pipeline (record → upload → transcribe-chunk → live transcript) is new work with the most moving parts (server, queue, ordering, offline).
5. **Web compatibility unknowns**: `expo-av` recording, `expo-file-system/legacy`, `expo-secure-store`, `expo-print`/`expo-sharing`, camera/document pickers behave differently or not at all in the browser. Every Phase 2+ feature must be checked on web, not just iOS. No current 3-column/responsive web layout exists.
6. **No rich-text editor** and no ProseMirror model. TenTap custom extensions need an **EAS dev build** (won't run in Expo Go) — Phase 4 depends on Phase 4.1 (dev build) and the 4.2 spike proving iOS↔web JSON parity.
7. **No marks / live notes / block-origin model** — three core product promises (notes always included, edits never overwritten, marks steer the summary) have **no schema support** today. They land in the Phase 1 schema (`marks`, `note_lines`, document blocks with origin) and Phases 5/7.
8. **Streaming not used** — assistant chat (Phase 6) needs streaming responses; current AI calls are one-shot `fetch`. Edge Function + client streaming is new.
9. **Model ids are scattered and partly legacy** (`claude-sonnet-4-6`, `claude-sonnet-4-20250514`, `claude-haiku-4-5`, `whisper-1`). Plan wants model names in **one config place** (Step 1.6). Verify current recommended Claude model at that point.
10. **No sync / conflict model** — moving to two devices (Phase 1.8) needs a conflict rule (plan: newest-wins per block, loser kept in version history). SQLite becomes a cache; migration of existing local data (1.9) must be idempotent and non-destructive.
11. **Palette is incomplete for the designed summary**: `colors.ts` lacks tokens DESIGN.md/SUMMARY-SPEC.md call for — recording `#CC3333` (only `error: #D94F4F` exists), "From your notes" green `#E8F5EE`/`#1F6B45`, exam `#FFFBEB`/`#FFE4B5`/`#7A4A00`, accent-on-light `#4F43B0`, salmon label `#8A3B22`. CLAUDE.md says never hard-code a hex that "already exists" — these don't yet, so they must be **added to `colors.ts`** (likely Phase 2.3 / Phase 4.6), not inlined.
12. **Consent gate missing** (Apple 5.1.2(i)) — audio/transcripts/photos go to OpenAI/Anthropic with no explicit consent screen. Launch blocker; Phase 10.1.
13. **PDF offline-fonts/KaTeX**: current `pdf-template.ts` is basic HTML; the spec needs base64-embedded fonts + pre-rendered KaTeX so export works offline (Phase 8.3).

## 4. What each phase can reuse

- **Phase 1 (backend):** `db.ts` schema + `types/database.ts` mirror an old Postgres schema → strong starting point for the SQL migrations. `AuthProvider`/`useAuth`/`session.ts` shape can be kept while swapping the backing store to Supabase Auth. `mappers.ts` pattern (row↔domain) carries over. `storage.service.ts` already abstracts file storage behind a small helper — reswap its body to Supabase Storage. `ai.service.ts` already isolates all AI calls → move their bodies into Edge Functions, keep the call sites. `ai-usage.service.ts` + `ai_usage` table + `credit-check.service.ts` map onto server-side usage/limits. The **mock pipeline** stays for offline dev (Step 1.7 keeps it).
- **Phase 2 (shell):** `constants/colors.ts`, `constants/typography.ts`, `components/Avatar.tsx`, `SplashScreen.tsx`, the expo-router `(auth)`/`(main)` group + tabs structure, `NewProjectModal` color palette. Extend colors.ts (risk #11) here.
- **Phase 3 (library):** `folder.service.ts`, `project.service.ts`, `session.service.ts`, `MoveToModal.tsx` (keep as the accessible fallback), `UndoToast.tsx`, `trash.service.ts` (+`settings/trash.tsx`), `search.service.ts`, `source-file.service.ts`, `project/[id].tsx` breadcrumb logic. Drag-and-drop (3.1 spike) and Star/Exam-packs/Review-today are net-new.
- **Phase 4 (editor):** `note/[id].tsx` (fields, transcript collapse, highlight) informs the Summary/Transcript tabs; `HighlightableText.tsx` + the clarify flow seed "Ask Claude on selection". Editor itself (TenTap/Tiptap), tabs, version history, block-origin are net-new. `export.service.ts`/`pdf-template.ts` are the base for Phase 8.3.
- **Phase 5 (recording):** `record/active.tsx` (chunking/pause/resume/timer/bg-audio), `record/index.tsx` (setup: project/language/mode, mic permission), `storage.service.ts`, `source-file.service.ts`, `session.service.ts`, `transcript.service.ts`, `utils/permissions.ts`, `utils/file-size.ts`. Migrate expo-av→expo-audio; add marks, live notes, waveform, 30-sec chunks, live transcript.
- **Phase 6 (assistant):** `ai.service.clarifyContent` + `note.service` clarification storage as the pattern; `credit-check.service.ts` for limits. Chat UI, streaming, `assistant_messages`, quick prompts, Add-to-notes/Flashcards are net-new.
- **Phase 7 (summary):** `ai.service.generateNotes` + `buildSystemPrompt`/`buildModeInstruction` as the prompt-building pattern; `utils/tokens.ts` (`estimateTokens`) for word/token math; `settings.service.ts`/`user_settings` for course defaults. Derived-variable calculator, 10 sliders, subject modules, zod schema, coverage/quality checks are net-new.
- **Phase 8 (visuals & PDF):** `export.service.ts`, `utils/pdf-template.ts` (`generateNoteHTML` + section renderers) as the PDF base. Module components, KaTeX, plots/charts are net-new.
- **Phase 9 (study):** `user_settings` + `settings/general.tsx` pattern for course settings; `types/database.ts` conventions for new `flashcards`/`review_schedule` tables.
- **Phase 10 (launch):** `auth.service.deleteAllUserData` + `settings/account.tsx` as the account-deletion UI base; `ai_usage` + budgets for pricing/limits; `app.json` permission strings as the base for the full permission/consent set.

> Reuse rule (CLAUDE.md): don't rewrite working services/components — adapt them. The biggest single change is swapping the persistence/AI layer under services that are otherwise shaped correctly.
